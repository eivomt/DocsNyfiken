unitaryStep()

unitaryStep() takes no arguments, it uses and makes changes to global variables, and returns \psi(t+dt) , along with some tensors used for the draw pass.
The meat of this function is an implementation of the split operator method, since this is shared between unitaryStep() and step(), this has a separate explanation.

preparing the wavefunction for visualization

The rest of the function, as can be read above gets |\psi|^2 but does not return it 'raw'. Adding probInWell to |\psi|^2 is what makes the visualization show a wavefunction 'in' the potential well. The potential and the wave function strictly speaking do not live in the same coordinate system. The y-axis for the potential shows energy, whereas the y-axis for |\psi|^2 is a probability amplitude. An argument could be made that a wave function sloshing about in a well is a misleading picture of the underlying dynamics. Another argument could be made which goes something like, who cares, this looks and feels better, and I tend to agree with the latter.

So the top half of the snippet above is a conceptually misleading massage of the wave function, and the rest is a hack covering up for a bug we never found the cause of. Not our finest moment, i'll admit.

The bug in question; each time step we noticed a small but, given enough iterations, not unnoticeable growth in the total amplitude of the wavefunction. If we were to take that result seriously it would mean the probability of finding the particle at some point on screen is greater than 1. Disaster! We fix this by renormalizing if the total probability > 1. We do not renormalize if the total probability is less than 1, since that is allowed by the absorber.
