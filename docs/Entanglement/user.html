User

Once a superuser has connected, subsequent clients are treated as regular users. Regular users do not control the global simulation state; their role is limited to performing measurements by interacting with the coin.

If the superuser disconnects, the server state can become inconsistent. As a manual recovery mechanism, any connected client can run disconnectAll() in the browser console. This closes all active connections to the server. The next client to connect will then become the new superuser.

User Interaction

A regular user has one primary action: clicking the coin. This sends a measurement request to the server. The server responds with a definite outcome, after which the client updates the display to show either the blue or red result.

When a measurement has been made, the superposition animation stops. The screen changes to the corresponding colour, and only the SVG associated with the measured outcome remains visible.

Stroke Animation

The animated drawing effect on the SVGs is produced by applying a stroke animation to every path in the graphic. Each path has a different length, so a separate keyframe animation is generated for each one. 

        paths.forEach((path, index) => {
            const length = path.getTotalLength();

            path.style.strokeDasharray = length;
            path.style.strokeDashoffset = length;

            const animationName = `kron-${index}`;

            const styleSheet = document.styleSheets[0];
            styleSheet.insertRule(`
                @keyframes ${animationName} {
                    from {
                        stroke-dashoffset: ${length}
                    } to {
                        stroke-dashoffset: 0;
                    }
                }
            `, styleSheet.cssRules.length);

            path.style.animation = `${animationName} 4s ease-in-out infinite alternate`;
            path.style.animationDelay = '2.75s';
        });

The animation works by first hiding each path stroke using strokeDashoffset. The offset is then animated from the full path length down to zero, creating the appearance that the SVG is being drawn over time. The infinite alternate setting causes the animation to continuously reverse direction.

Collapse

Once the server returns a measurement result, the client collapses the visual state by calling either cutToBlue() or cutToRed(). These functions are structurally identical; they differ only in which colour and SVG are displayed. The example below shows the blue outcome. 

        cutToBlue = () => {
            Mynt.classList.add('hidden');
            Kron.classList.add('hidden');

            coinContainer.classList.add("hard-blue");
            coin.removeEventListener("click", sendCoinClick);

            setTimeout(() => {
                for (let i = 0; i < myntPaths.length; i++) {
                    myntPaths[i].style.animation = 'none';
                    myntPaths[i].style.strokeDasharray = length;
                    myntPaths[i].style.strokeDashoffset = 0;
                }

                for (let i = 0; i < kronPaths.length; i++) {
                    kronPaths[i].style.animation = 'none';
                }

                Mynt.classList.remove('hidden');

                collapsed = true;
            }, 200);
        };

The function first hides both SVGs and applies the background class for the selected outcome. It then removes the click listener from the coin, preventing the user from sending additional measurement requests before the state is reset.

After a short delay, the stroke animation is disabled. The relevant SVG is made fully visible by setting its stroke offset to zero and removing the hidden class. Finally, collapsed is set to true, marking the client as being in a measured state.

The fade effect is controlled through CSS: 

        button {
            transition: .2s cubic-bezier(0.075, 0.82, 0.165, 1);
        }

        .hidden {
            opacity: 0;
        }

Server Handling: coin_clicked

When a user clicks the coin, the client sends a coin_clicked message to the server. The server determines whether the user belongs to a pair and, if so, calculates the appropriate measurement outcome. 

        if data.get("type") == "coin_clicked":
            sender_ws = websocket
            sender_id = connected_clients[sender_ws]["id"]

            partner_ws = get_partner(sender_ws)
            if partner_ws is None:
                await sender_ws.send(json.dumps({
                    "type": "coin_clicked",
                    "inGroup": False
                }))
                continue

            partner_id = connected_clients[partner_ws]["id"]
            pair_key = get_pair_key(sender_ws, partner_ws)

            first_measurement = False

            if Entangled:
                if pair_key not in pair_states:
                    base = random.choice([0, 1])
                    pair_states[pair_key] = {"collapseTo": base}
                    value = base
                    first_measurement = True
                else:
                    base = pair_states[pair_key]["collapseTo"]
                    value = 1 - base if Opposite else base
            else:
                value = random.choice([0, 1])

            collapsed_values[sender_id] = value

            await sender_ws.send(json.dumps({
                "type": "coin_clicked",
                "inGroup": True,
                "partner": partner_id,
                "value": value,
                "firstMeasurement": first_measurement
            }))

The server first identifies the sender and checks whether they are paired with another user. If no partner is found, the server responds with inGroup: false and no collapse is performed.

If the sender is part of a pair, the server determines the measurement value. For non-entangled pairs, the value is chosen randomly. For entangled pairs, the first measurement generates and stores a shared base value. Later measurements by the paired user are derived from this stored value. If Opposite is enabled, the partner receives the opposite result; otherwise, both users receive the same result.

The selected value is stored in collapsed_values and returned to the client as a coin_clicked response.

Client Handling: coin_clicked

When the client receives a coin_clicked response, it reads data.value and displays the corresponding result. 

        case 'coin_clicked':
            if (!superUser) {
                if (data.value === 1) {
                    cutToRed();
                } else if (data.value === 0) {
                    cutToBlue();
                }
            }
            break;

A value of 1 triggers cutToRed(), while a value of 0 triggers cutToBlue(). Any debug logging around this block can be removed once the interaction is stable.

Resetting the System

When the superuser presses reset measurements, the client sends a reset-all message to the server. The server clears all stored pair states and collapsed values, then broadcasts a reset message to every connected client. 

        if data.get("type") == "reset-all":
            pair_states.clear()
            collapsed_values.clear()

            for client, info in connected_clients.items():
                try:
                    await client.send(json.dumps({"type": "reset"}))
                except Exception as e:
                    print(f"Error sending to client {info['id']}: {e}")

On the client side, the reset message restores the visual superposition and re-enables clicking on the coin. 

        case 'reset':
            cutToWhite();
            coin.addEventListener("click", sendCoinClick);
            break;

cutToWhite()

cutToWhite() returns the client to the unmeasured superposition state. It removes the hard red or blue background, hides both SVGs temporarily, and then restarts the stroke animations for both outcomes. 

        cutToWhite = () => {
            coinContainer.classList.remove("hard-blue");
            coinContainer.classList.remove("hard-red");
            Mynt.classList.add('hidden');
            Kron.classList.add('hidden');

            setTimeout(() => {
                for (let i = 0; i < myntPaths.length; i++) {
                    zeroPath(myntPaths[i]);
                    myntPaths[i].style.animation =
                        `mynt-${i} 4s ease-in-out infinite alternate`;
                }

                void myntPaths[0].offsetWidth;

                Mynt.classList.remove('hidden');

                for (let i = 0; i < kronPaths.length; i++) {
                    zeroPath(kronPaths[i]);
                    kronPaths[i].style.animation =
                        `kron-${i} 4s ease-in-out infinite alternate`;
                    kronPaths[i].style.animationDelay = '2.75s';
                }

                Kron.classList.remove('hidden');

                void kronPaths[0].offsetWidth;
                collapsed = false;
            }, 350);
        };

The two SVG animations are restarted with a slight offset, so the coin appears as a continuous visual mixture of the two possible outcomes rather than as a single definite state. Finally, collapsed is set to false, allowing the client to participate in a new measurement after the next click.
